- 正確答案套話：「此選項最直接符合題目的需求與限制，通常能在效能、可用性、安全性、成本與維運複雜度之間取得最佳平衡。」

三句都沒有針對題目內容做任何實際技術判斷，使用者要求全部換成真正有 AWS 技術含量的詳解。

## 你要做的事
對 `remaining_questions.json` 裡的每一題，根據 `q`（題目）、`opts`（選項原文）、`ans`（正確答案字母）撰寫詳解，輸出成 `generated_explanations.json`（格式見下方），然後跑：

```bash
python tools/explanation-rewrite/apply_explanations.py \
  tools/explanation-rewrite/remaining_questions.json \
  tools/explanation-rewrite/generated_explanations.json
```

這支腳本只會替換 `saa_003_zh-TW.md` 裡對應題目的 `**詳解**` 區段，`**題目**/**選項**/**答案**/**社群投票**/**分類**` 完全不會被動到。腳本每次執行都會**重新掃描目前檔案的實際行號**，所以：
- 可以分批多次執行（例如寫好 50 題就跑一次，再繼續寫下 50 題再跑一次）。
- 對同一批資料重跑兩次會得到完全相同的結果（idempotent），不用擔心重複執行。

`generated_explanations.json` 格式：
```json
[
  {
    "n": 684,
    "options": [
      {"letter": "A", "correct": false, "explanation": "..."},
      {"letter": "B", "correct": true,  "explanation": "..."},
      {"letter": "C", "correct": false, "explanation": "..."},
      {"letter": "D", "correct": false, "explanation": "..."}
    ]
  }
]
```
- `options` 要包含該題**全部**選項字母（含正確答案本身），不要漏。
- `correct` 只是給腳本做 sanity check 用，最終正確答案是以 `remaining_questions.json` 裡的 `ans` 欄位為準（原始題庫的正解不能被 AI 判斷覆蓋），所以就算你判斷錯 `correct` 也不會弄壞正解，但還是盡量填對。
- `explanation` 只寫該選項自己的說明文字，**不要**加 `- X：` 前綴、**不要**重複選項原文（腳本會自動把原始選項文字接在你的說明前面）。

## 寫作要求（繁體中文 zh-TW）
**嚴禁使用以下這幾種空話（一字不漏或意思相同的變體都不行）**：
- 「此選項最直接符合題目的需求與限制，通常能在效能、可用性、安全性、成本與維運複雜度之間取得最佳平衡」
- 「此做法可行性較低、成本或維運複雜度較高，或不完全符合題目限制」
- 「此選項符合題目條件，能有效滿足核心需求」

- **正確答案的選項**：具體說明對應的 AWS 服務/機制運作原理，以及它為什麼能滿足題目描述的需求與限制（提到關鍵字，如服務名稱、特性、限制條件的對應），2–4 句。若有多個正確答案（`ans` 含逗號，如 `"A,C"`），每個正確選項都要有自己的具體理由，不能共用同一句話。
- **錯誤選項**：具體指出「這個選項的技術內容」為什麼不適用——可能是服務類型不對、缺少某個能力、不符合題目的某個明確限制（例如頻寬、延遲、成本、維運複雜度、資料量、安全性要求等），1–3 句。每個錯誤選項的理由必須針對該選項的實際內容分別撰寫，不可以讓多個選項共用同一句話術。
- 若某一題的選項文字本身缺漏或明顯亂碼（資料源本身的問題，例如題號 477 選項是壞掉的 JSON 片段），就依現有可讀資訊盡力給出合理判斷，不用勉強編造。

風格參考（已經寫得好的真實範例，達到這種具體程度即可，但不要抄用其中的服務名稱到別題）：

- 其餘選項比較：
- A：{選項 A 原文，句尾改成全形句號}{你寫的說明}

多選題（`ans` 為 `"A,C"` 這種）：所有正確答案的 bullet 會照 `ans` 裡的順序排在最前面，接著才是 `- 其餘選項比較：`，其餘照選項原順序排列。這些排序、標點轉換、bullet 組裝腳本都會自動處理，你只要提供每個選項的 `explanation` 文字。
